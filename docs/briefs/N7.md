## Goal
A **«Summarize with AI»** button summarises the open document with AI (scanned paper or file) and **highlights what has to be done**: dates, amounts, what to sign or send. The summary is shown on screen and read aloud.

## Interview decisions
- **What is summarised:** first, the whole document. The function accepts any text: the selection (N6) is connected when it exists.
- **Output:** on screen (large text) and read aloud with the local voice ($0 for the voice).
- **Model:** the cheap one first and the expensive one only if the cheap one does not do, like «explain». With a cache and the cost in the meter.
- **Cost limit:** $0.005 per summary with the demo profile (Haiku).
- **Style:**
  - 2–3 sentences;
  - then, a list of what has to be done;
  - plain language, in the document's language.

## Scope
- **Go** (`backend/session/summary.go`): `Summarize(text, lang)`.
  - Uses `CompleteWithEscalation`: it is in doubt if the cheap model does not return a JSON with a summary.
  - Trims long texts to 8,000 characters and says so.
  - Returns the summary, the actions, the text to read, the cost, the latency, the tokens and the model.
- **Wails binding** `Summarize(text, lang)` in `app_summary.go`. Without a key or without a network, it returns a clear sentence to read.
- **Interface** (`web/src/app/overlay/SummaryPanel.tsx`):
  - the button (also the S key), in overlay options 2 and 3, below the reader;
  - a panel with the summary, the actions and a cost line;
  - the app's `Speaker` reads it, which pauses the reader.

## Out of scope

- A keypad key (optional, page 2 of N2).

## Risks
- **Privacy:** the document's text leaves the computer (OpenRouter).
- **Budget:** escalating to Sonnet costs more. It only happens if Haiku does not return the format.
- **Long documents:** only the beginning is summarised (8,000 characters).
