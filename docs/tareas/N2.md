Owner: Isaac · Depends on: — (actions: N1, N4) · Board: `TAREAS.md` · How to start: `docs/TRABAJAR.md`.

## Goal
Keypad. Make the keypad work really well. The person who picks it up decides the details: ask them which keyboard and which actions.

## Current status
**Branches:** since #44 (2026-11-22), `main` holds the integration (#38), the per-person startup (#39), guided reading (#40) and the overlay app. What is cited from `feature/T6-camera-controls` (#41, Nil) is not in `main` yet: check whether it has been merged already.

- **There is no code that talks to the keypad.** In the code, «keypad» and «Logi Options» only appear in comments (`app_overlay.go`, `backend/overlay/hotkey.go`, `main.go`, `web/src/app/overlay/`, `web/src/document/`). The other matches for «Logitech» (`web/src/camera/select.ts`, `scanner/capturar.py`) are used to pick the Logitech **camera**.
- **The current design assumes the keypad sends normal key combinations**, mapped in Logi Options+ (comment in `backend/overlay/hotkey.go`):
  - the global shortcut (`LAUZHACK_HOTKEY`, by default `ctrl+alt+space`) shows and hides the overlay;
  - the overlay menu accepts keys 1–3 and also Num1–3 (`web/src/app/overlay/modes.ts`);
  - the guided reader (#40, `web/src/document/reader.ts`, `keyAction`) has single-key shortcuts (arrows, letters and the numeric keypad).
- **Old decisions in `AGENTS.md`:**
  - at first, the keypad and the haptic mouse were **parked**;
  - if the Logitech SDK required Python or C#, it would go as a separate adapter in `adapters/logitech/`, which does not exist;
  - `docs/ARQUITECTURA.md` leaves «to find out at the Logitech stand» what the SDK exposes.
- **Untested with a real keypad:** Isaac's brief leaves it unchecked.

## Open questions
For the person who picks up the task; they cannot be answered by reading the repo.
- Which exact keyboard it is (model: MX Keypad, the MX Creative console or another) and whether it has screens on the keys or a wheel or dial.
- How it connects: only with mappings in Logi Options+ (key combinations) or with the Logitech SDK or plugins. If it is the SDK, in which language (decides whether `adapters/logitech/` is needed).
- Which action goes on each key, per screen or mode (overlay menu, reader, gestures, cursor…).
- What «works really well» means: no lag, working with the app in the background, icons or text on the keys, a spoken notice on press…
- Whether it must work on other systems or only on the demo laptop (Windows).
- Whether the mappings are shared as a configuration file in the repo.

- Each action tested with the real keypad, also with the app in the background where it applies.
- Instructions to set it up on another computer in under 5 minutes.
