# N4. Button in the PDF to read the whole PDF aloud

Owner: Didac · Depends on: — · Board: `TAREAS.md` · How to start: `docs/TRABAJAR.md`.

## Goal
A button in the PDF to read the whole PDF aloud.

## Current status
**Branches:** since #44 (2026-11-22), `main` holds the integration (#38), the per-person startup (#39), guided reading (#40) and the overlay app. What is cited from `feature/T6-camera-controls` (#41, Nil) is not in `main` yet: check whether it has been merged already.

- **Read a file from the PC** (overlay, Didac): option 3 (`web/src/app/overlay/ReadFileMode.tsx`) follows this chain:
  1. the `OpenAndReadFile` binding (Go);
  2. the service's `POST /document` (`scanner/documents.py`: PDF with text, scanned PDF, images, TXT/MD);
  3. `GuidedReader`.
- **Guided reading** (#40, `web/src/document/`):
  - reads line by line with automatic advance until «End of document» (`reader.ts`, states `playing`, `paused` and `finished`);
  - highlights the line being spoken;
  - pause, previous, next and repeat, with keyboard shortcuts;
  - uses the browser's local voice (`voice.ts`, Web Speech), at no cost.
- **There is no PDF viewer:** the document's lines are shown in large type.
- **Tests:** according to Isaac's brief, a 21-line letter was read in 16 ms. Not verified by the person writing this.

## Open questions
For the person who picks up the task; they cannot be answered by reading the repo.
- «Button in the PDF»: a PDF viewer with a button on top, or the button of the current line view?
- Voice engine: the local one (free, as now) or a cloud one (better quality, with a cost).
- Controls needed: pause, stop, speed, skip a page.
- Highlighting of the text being read: on the PDF, on the lines (as now) or both?
- Long PDFs: page limit, reading by pages, acceptable preparation time.
- Voice language (today the document's is used if it has one).
