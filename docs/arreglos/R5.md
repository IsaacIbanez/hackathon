# R5. Window flow: the overlay rules and the gestures coexist

Owner: **Pau** (asked for on 2026-11-22). How to work: `docs/TRABAJAR.md`. Model and rules: **`docs/VENTANA.md`**.

## What fails (seen on 2026-11-22)
- Windows open, minimise and close in no particular order: less important processes, like the Hand Control menu, wreck the overlay, which is the parent process.
- Gesture Control has to coexist with everything else.

## Log
- **Chaos of window shapes.**
  - **Symptom:** when closing the fist menu, the overlay stayed at 960×680; cursor mode shrank it to the bubble and then reopened it; when closing AI Summary, 960×680.
  - **Reproduce:** `.exe` → menu → make a fist and open it.
  - **Cause:** six functions moved the window with loose flags, without knowing which shape was due when they finished.
  - **Fix:** a single controller (`windowInputs` → `desiredShape` → `applyShape`). Hierarchy: summary > fist menu > overlay (layer or window) > camera bubble > hidden. Also, cursor mode no longer touches the window.
  - **Checked:** `go test -run Shape .` and a run with the `.exe` with screenshots and the log: `window -> layer`, `layer -> bubble`, `bubble -> layer`, `layer -> window`, `window -> layer`, `layer -> gesture-screen -> layer` (before, it ended at 960×680), `layer -> bubble`, `bubble -> layer`.
